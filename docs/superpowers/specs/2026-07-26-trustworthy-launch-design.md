# 高考英语小程序可信上线版设计

## 目标

让学生第一次进入小程序就能理解各功能用途，并确保所有评分、趋势和诊断都来自真实数据，不展示推算或固定占位结果。

## 上线原则

1. 不展示虚构数据。没有真实分项分数、历史对比或趋势时，隐藏对应模块或显示“暂无数据”。
2. 区分错误与优化。语法、拼写可以标为错误；内容补充和表达升级属于修改建议。
3. 输入与功能匹配。句子纠错使用短文本；观点与素材、草稿诊断支持多行长文本。
4. 入口自解释。每个陪练模式直接显示用途、输入内容和预期结果。
5. 默认状态安全。正式页面不预填可被误提交的示例作文。

## 页面设计

### 写作文

- 应用文：题目、作文正文分别支持输入和 OCR。
- 读后续写：原文材料、第一段段首句、第二段段首句、续写正文分别输入。
- 提交前校验当前题型的必填项。
- 等待期间显示阶段性状态提示，但不展示虚假百分比。

### AI 陪练

- 观点与素材：输入话题或观点，输出理由、例子和可用表达。
- 句子纠错：输入英文句子，输出真实错误和表达升级。
- 草稿诊断：输入题目和草稿，输出内容、结构、语言诊断及下一步。
- 使用多行输入框；切换模式时同步更新说明、快捷操作和占位文字。

### 批改报告

- 展示真实总分、诊断、逐句修改建议和亮点。
- 删除固定涨分和前端推算的四项分数。
- “错误清单”改名为“逐句修改建议”。
- 没有逐句建议或亮点时显示明确空状态，不注入假示例。

### 首页

- 只展示能由历史记录真实计算的数据。
- 没有平均分或能力指标时显示“暂无”。
- 统计卡提供点击反馈：练习数和平均分进入历史记录；能力项打开最近报告。

## 数据流

前端只转换和展示后端返回的数据，不从总分推导分项分数。历史统计只使用成功的正式批改记录。陪练记录不混入正式批改平均分。

## 错误处理

- 缺少题目、原文、段首句或作文时，在提交前给出具体提示。
- OCR 失败保留用户已有输入。
- 请求失败停止进度提示，并允许用户修正后重试。

## 验证

1. 数据转换测试覆盖总分解析、无分数状态、建议分类和首页统计。
2. JavaScript 语法检查和差异格式检查通过。
3. 微信开发者工具中验证应用文、读后续写、三种陪练、报告空状态和首页导航。
4. 体验版真机验证登录、OCR、提交、历史记录、超时和弱网提示。
